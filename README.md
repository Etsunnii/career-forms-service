# Форма — сервис форм отклика

Автономное приложение для менеджеров карьерной платформы и студентов. Менеджер собирает форму, публикует уникальную ссылку и просматривает отклики. Студент открывает ссылку и отправляет ответы.

## Запуск

Нужен **Node.js 20 или новее**. Из корня репозитория выполните ровно две команды:

```sh
npm install
npm start
```

Откройте **http://localhost:3000** или **http://localhost:3000/admin**. Авторизация не нужна, как требуется в ТЗ. Сборка, API-ключи, облачные сервисы и отдельная СУБД не требуются. В приложении нет внешних шрифтов, CDN и сетевых запросов к сторонним сервисам. Сторонних npm-зависимостей также нет.

Порт задаётся переменной окружения `PORT`:

```powershell
# Windows PowerShell
$env:PORT = '4000'
npm start
```

```sh
# macOS / Linux
PORT=4000 npm start
```

После изменения порта откройте соответствующий адрес, например http://localhost:4000/admin. Публичные ссылки формируются с учётом текущего адреса приложения.

## Основной сценарий

1. В админке нажмите **«Создать форму»**. Выберите чистый лист либо шаблон стажировки или события.
2. Укажите название, описание и вопросы. Доступны короткий и длинный текст, email, число, выпадающий список, один или несколько вариантов. Укажите обязательность и измените порядок стрелками.
3. Нажмите **«Сохранить»**, затем **«Опубликовать»**. Публикация также сохраняет текущий черновик. Пустую форму опубликовать нельзя.
4. Скопируйте ссылку `/f/<уникальный идентификатор>` и откройте её в другой вкладке — это страница студента. Отправьте ответы.
5. Вернитесь в редактор, откройте **«Ответы»** и нажмите **«Обновить»**. Раскройте отклик, чтобы посмотреть все ответы.
6. **«Закрыть приём»** делает ссылку недоступной для заполнения. Уже полученные ответы остаются в админке. Повторная публикация использует ту же ссылку.

На главной странице есть поиск форм, число откликов и общая конверсия. В редакторе доступен предпросмотр без отправки реальных ответов. На узком экране интерфейс перестраивается для телефона.

## Хранение и версии

- Данные автоматически сохраняются в `data/forms.json` внутри проекта. При первом запуске список форм пуст. Данные переживают перезапуск сервера.
- Файл создаётся после первой операции записи. Он исключён из Git, чтобы реальные ответы не попадали в публичный репозиторий. Для резервной копии остановите сервер и скопируйте этот файл.
- Изменения сначала попадают в черновик. Студенты видят опубликованную копию до нажатия **«Обновить публикацию»**.
- Каждый отклик хранит снимок вопросов и номер версии. Переименование или удаление вопроса не меняет старые ответы.
- При обновлении публикации уже открытая старая форма отклоняет отправку с понятным сообщением. Пользователь может скопировать ответы и обновить страницу.
- Записи проходят через очередь транзакций; файл сначала записывается во временный файл, затем заменяется атомарным переименованием. Ошибки валидации и записи не меняют текущее состояние в памяти. Повреждённый JSON останавливает запуск, а не заменяется пустой базой.
- Хранилище рассчитано на **один процесс Node.js** и небольшое число форм и откликов, соответствующее MVP. Не запускайте несколько серверов с общим файлом данных. Для большого объёма потребуется пагинация и другое хранилище.

## Воронка

Для каждой формы считаются:

- **Открыли форму** — уникальные сессии посещения в рамках вкладки браузера.
- **Начали заполнять** — первое изменение любого ответа.
- **Отправили отклик** — успешно сохранённые отклики.
- **Конверсия** — отношение откликов к посещениям.

Идентификатор хранится в `sessionStorage`. При недоступном хранилище используется сессия в памяти страницы. Повторные запросы с одним идентификатором не дублируют посещения или отклики, включая одновременные повторные отправки. Это счётчик сессий, а не людей: новая вкладка или другой браузер могут создать новую сессию. По воронке можно увидеть потери между этапами; она не устанавливает точную причину ухода и не отслеживает отдельные поля. Блокировка запросов статистики может повлиять на точность.

## Проверка

```sh
npm test
```

Тесты используют встроенный `node:test`, временные файлы и свободные локальные порты. Рабочие данные не затрагиваются. Проверяются полный сценарий MVP, сохранность после перезапуска, ошибки ответов и схемы, изоляция черновика, снимки старых вопросов, закрытие приёма, повторные и параллельные отправки, ограничения запросов и защита файла данных.

Серверная проверка обязательных полей, email, чисел и вариантов ответа работает независимо от браузера. Ограничения: до 40 вопросов, до 30 вариантов на вопрос, до 500 символов в коротком ответе и до 5 000 в длинном. Пользовательский текст экранируется при выводе. Сервер разрешает только заданные статические файлы, задаёт CSP и отклоняет браузерные изменения с чужим Origin.

Админка и её API намеренно открыты согласно ТЗ. Ссылку на форму можно открыть на другом устройстве, если сервер доступен по сети: вместо `localhost` используйте адрес машины. В этой версии нет разграничения доступа к админке; это локальный MVP.

## Структура

```text
server.js              HTTP-сервер, маршруты и API
lib/store.js           локальное JSON-хранилище и очередь записи
lib/validation.js      проверка схем форм и ответов
public/                интерфейс на HTML, CSS и JavaScript
test/app.test.js       интеграционные тесты
data/                  данные приложения, не публикуются в Git
AI_WORK_LOG.md         журнал использования AI и решений
```
