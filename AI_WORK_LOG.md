# Журнал работы с AI

Дата: 20 октября 2026 года. Инструмент: OpenAI Codex в настольном приложении.

Это краткий журнал запроса, выполненной работы и решений. Он не является дословным экспортом чата. Исходная переписка остаётся в чате Codex и не удалялась; её можно показать на финальных этапах собеседования. Скрытые внутренние рассуждения и учётные данные в журнал не включаются.

## Запрос

Пользователь: «сделай всё точно по тз».

Источник требований: предоставленный двухстраничный PDF «ТЗ Младший веб-разработчик.pdf». Документ прочитан по изображениям обеих страниц. Обязательные требования отделены от необязательных идей: главное — конструктор, публикация, отправка и просмотр ответов. Важны Node.js 20+, две команды запуска, порт 3000 / PORT, автономность и открытый `/admin`.

## Реализация с помощью AI

1. Проверена пустая папка проекта и доступность Node.js/npm.
2. Выбран стек без сторонних npm-зависимостей: встроенный HTTP-сервер Node.js, локальный JSON и браузерный JavaScript.
3. Реализованы конструктор, шаблоны, предпросмотр, публикация и закрытие приёма, страница студента и просмотр откликов.
4. Добавлены серверная валидация, разделение черновика и публикации, сохранение снимков вопросов, очередь записи и повторяемая отправка без дублей.
5. В качестве ограниченного дополнения выбрана воронка посещений, начала заполнения и отправки. Детальная аналитика по каждому полю, вложения и авторизация не включены.
6. Написаны интеграционные тесты на `node:test` и документация запуска.

## Принятые ограничения

JSON-хранилище обслуживается одним процессом; данные целиком загружаются в память. Админка открыта по прямому требованию ТЗ. Воронка считает сессии вкладок, а не уникальных людей. Внешние ресурсы и API в работе приложения не используются.

## Пересдача: 29 октября 2026 года

Пользователь сообщил об обратной связи FutureToday, попросил разобрать слабые места, затем исправить найденное. На исходном коммите `eae0ce5` отдельно воспроизведены четыре ошибки: поздний ответ сохранения стирал новый ввод; разные ответы в одной сессии получали ложное подтверждение; старая вкладка затирала новые вопросы; повторная публикация той же формы отклоняла уже открытые страницы студентов. Рабочая база в этих проверках не использовалась.

Внесённые исправления:

- Поля блокируются во время запросов. Логика состояния редактора выделена в `public/editor-session.js`; поздний ответ дополнительно сверяется со счётчиком изменений и не стирает новый текст.
- Добавлена отдельная версия черновика с проверкой внутри очереди записи. Конфликтующая вкладка сохраняет свои правки на экране; доступны открытие актуальной версии и скачивание своего черновика.
- Повторная доставка одинакового отклика возвращает прежний результат. Отличающиеся ответы той же сессии отклоняются с честным сообщением. Повторное открытие уже отправленной формы показывает подтверждение прежней отправки.
- Версия опубликованных вопросов меняется только при изменении схемы. Правки заголовка и описания, повторная публикация и повторное открытие неизменённой формы не вызывают лишний конфликт.
- Незавершённые ответы восстанавливаются из хранилища сессии. При изменении вопросов можно обновить форму и перенести совместимые ответы. Запрет браузерного хранилища не ломает отправку.
- HTTP-запросы и работа с черновиками студента вынесены в отдельные модули. Удалён неиспользуемый сценарий шаблона события.
- Добавлены `DECISIONS.md` с альтернативами и причинами выбора и `MANUAL_CHECKLIST.md` для проверки кандидатом.

Проверки: 19 автоматических тестов прошли на Node.js 24.16.0 и 20.20.2. В наборе есть серверные запросы, задержка и отказ сохранения, конфликт вкладок, потеря ответа после успешной записи, восстановление полей, миграция старого JSON и реальный отказ записи временного файла. Пять DOM-тестов используют `jsdom` 26.1.0 как зависимость только для разработки; код приложения работает без этой библиотеки. `npm install` не сообщил об известных уязвимостях установленных зависимостей.

Из чистой копии без рабочих данных выполнены `npm install` и `npm start` с `PORT=3188`: `/admin`, `/admin/forms` и все новые модули вернули HTTP 200, список форм был пуст. После проверки временный сервер остановлен. Перед запуском обновлённого рабочего сервера создана локальная копия базы в игнорируемой папке `output`; пять существующих форм доступны на `localhost:3000`. Рабочие ответы не отправляются в GitHub.

Граница проверки остаётся явной: настоящий браузерный инструмент не запускается из-за отсутствующего `browser-service.mjs`. DOM-тесты проверяют обработчики и значения полей, но не визуальную отрисовку. Ручной чек-лист оставлен без отметок выполнения. Решения сформулированы агентом; самостоятельное выполнение и понимание кандидатом не приписываются ему автоматически.
